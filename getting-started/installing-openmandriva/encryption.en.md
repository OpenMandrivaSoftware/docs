# Disk Encryption

Disk encryption protects your data when someone has physical access to your computer—whether that is a stolen laptop, a discarded hard drive, or an unattended device. Without encryption, anyone can remove the drive, connect it to another computer, and read all your files. Encryption scrambles the data so it is useless without the right key. Linux file system encryption uses the Linux Unified Key Setup (LUKS), and *Calamares* supports it through a checkbox in the partitioning screen.

## How LUKS Works

Linux file system encryption uses the Linux Unified Key Setup (LUKS). When you encrypt a partition with LUKS, a master key encrypts all data written to that partition. The master key itself is stored on the disk, protected by a passphrase that you choose at boot time.

The boot process works as follows:

1. *GRUB* loads from the unencrypted EFI or boot partition.
2. GRUB prompts for the LUKS passphrase.
3. You enter the passphrase, which unlocks the master key.
4. The master key decrypts the root partition, and the boot continues normally.

The same mechanism protects encrypted swap partitions. You can also add a keyfile—typically generated by Calamares and stored in the initramfs—so that the system unlocks automatically when booted from the internal drive but remains protected when removed.

{: .note }

LUKS operates below the file system layer. Whether you use ext4, Btrfs, or any other file system on top of an encrypted partition, the encryption and the passphrase prompt are identical.

## What Calamares Supports

Calamares supports LUKS full-disk encryption through a checkbox in the partitioning screen. The checkbox appears in partitioning modes that create or format partitions:

- **Erase disk and install** — enable the encryption option before proceeding. Calamares encrypts the root partition and prompts you for a passphrase.
- **Format a partition and install** — check the **Encrypt** box when formatting the target partition.
- **Manual partitioning** — when you create or edit a partition, check the **Encrypt** box and enter a passphrase.

### Limitations in OpenMandriva

As of the current release, OpenMandriva ships Calamares with LUKS1 support. LUKS2 is available in newer versions of Calamares and GRUB, but the GRUB version in OpenMandriva cannot unlock LUKS2 partitions that use the argon2id key derivation function. If you need LUKS2, you must pre-create the encrypted partition with *GParted* or `cryptsetup` before running Calamares, then assign it a mount point in manual mode.

Calamares cannot encrypt the EFI System Partition (`/boot/efi`). This partition must remain unencrypted so that GRUB can load and prompt for the passphrase. If you use manual partitioning, create a separate small (300&ndash;512 MB) unencrypted FAT32 partition for `/boot/efi`.

Calamares also cannot create an encrypted `/boot` partition with GRUB2 in OpenMandriva. If your root partition is encrypted, Calamares keeps `/boot` inside the encrypted volume, which works as long as the kernel image does not depend on early loading of encryption modules.

## When to Encrypt

Encrypt your disk in these situations:

- You travel with a laptop and want protection against theft.
- You store sensitive personal data (financial records, documents, credentials).
- You plan to dispose of or sell the drive.
- Your employer or legal counsel requires encryption.

You can safely skip encryption for these cases:

- The computer stays in a locked room or desk.
- All sensitive data lives on a network drive you access remotely.
- You use full-disk encryption at the application or container layer instead.
- You need the flexibility to recover files without entering a passphrase at every boot (for example, on a headless home server).

## Planning an Encrypted Installation

Before starting Calamares, decide on your layout. A typical encrypted installation looks like this:

| Partition | Size | File system | Encrypted? |
| --- | --- | --- | --- |
| `/boot/efi` | 300&ndash;512 MB | FAT32 | No |
| `/` (root) | Remaining space | ext4 or Btrfs | Yes |
| `swap` | Optional | swap | Yes (if created) |

1. Boot the live session and open GParted if you want to pre-create partitions.
2. Create a small FAT32 partition for `/boot/efi`.
3. Create the root partition with your chosen file system.
4. Start Calamares and select **Manual partitioning**.
5. Assign the FAT32 partition to `/boot/efi` without checking **Encrypt**.
6. Assign the root partition to `/` and check **Encrypt**.
7. Set your passphrase and complete the installation.

{: .warning }

If you forget to create an unencrypted `/boot/efi` partition on a UEFI system, Calamares may encrypt the entire disk and the system will not boot. Double-check your partition assignments before clicking *Install*.

## Recovery Considerations

Recovery from an encrypted installation is more involved than from a plain one:

- **Boot repair** — if GRUB is damaged, you must unlock the LUKS volume from a live USB before reinstalling GRUB. The commands are `cryptsetup luksOpen`, `mount`, `chroot`, then `grub2-install`.
- **Drive replacement** — moving an encrypted installation to a new drive requires cloning the LUKS header and all data partitions. Tools like `dd`, *Clonezilla*, or *FSArchiver* work, but you must copy the LUKS header with `cryptsetup luksHeader backup`.
- **Passphrase loss** — if you forget the passphrase and did not save a keyfile or recovery token, the data is gone. Write the passphrase down and store it securely.

{: .tip }

Before you encrypt, write down your passphrase and store it in a safe place. Calamares does not generate a recovery key, and LUKS does not have a recovery mode.
